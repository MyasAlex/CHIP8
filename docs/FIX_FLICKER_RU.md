# Исправление мерцания в CHIP-8 Studio 2.1

Пользователь подтвердил работоспособность версии 2.0 на своём компьютере и сообщил о пропадании движущихся элементов в исходном Pong с ботом и Breakout. Собственный ROM Pong на двух игроков выглядел плавно.

## Проверка ROM

ROM побайтно совпадают с исходным пользовательским ZIP и файлами из [опубликованного набора](https://github.com/kripod/chip8-roms):

| ROM | Размер | SHA-256 | Совпавший файл набора |
|---|---:|---|---|
| Pong | 246 байт | `29950384966d7ecac743fd189ff5123d1617ce379f11b734bbac22667c4aca23` | `Pong (1 player).ch8` |
| Breakout | 280 байт | `437c1cda2418b5a683ac98ee32e0fc44089c2744b45d8e344c4912363831defa` | `Breakout (Brix hack) [David Winter, 1997].ch8` |

Изменения или повреждения этих ROM не объясняют наблюдаемое мерцание.

## Причина и изменение

Обе игры стирают старое положение мяча XOR-операцией, выполняют расчёты и рисуют новое. В типичном проходе между стиранием и рисованием проходит 11 инструкций — около 15,7 мс при 700 инструкциях/с. У Pong в измеренном прогоне встречались промежутки до 32 инструкций, около 45,7 мс. Ракетки стираются и рисуются между другими операциями.

Версия 2.0 учитывала лишь последнюю операцию рисования и могла удержать целый кадр один дополнительный период. Добавление одного объекта могло опубликовать незаконченный кадр с отсутствующим другим объектом.

Версия 2.1 получает метаданные каждого рисования в момент его выполнения. Стабилизатор сохраняет пиксели каждого чисто стёртого спрайта отдельно; при соответствующей повторной отрисовке удаляет прежнее положение и показывает новое. Соответствие определяется регистрами координат, размером и выбранными слоями. При нескольких спрайтах с одинаковыми регистрами выбирается ближайшая прежняя позиция. Данные спрайта сохраняются вместе с событием, поэтому последующие изменения RAM не меняют удержанный рисунок.

Удержание ограничено четырьмя границами кадра, максимум 66,7 мс. Непарное стирание обязательно станет видимым, даже если новых изменений экрана нет. Очистка, прокрутка и смена видеорежима отменяют удержание. Точный режим и принудительное обновление при отладке обходят стабилизатор. Изменений ROM, скорости, таймеров, XOR-логики и проверки столкновений нет; формат сохранений остаётся прежним.

## Проверки

- 47 групп тестов ядра, включая 6 новых групп стабилизации, прошли.
- Два ROM исполнены по 1200 кадров при 700 инструкциях/с. Для каждого кадра сериализованное состояние совпало с отдельным прогоном без стабилизатора.
- Для проверки пропадания отслеживалось последнее завершённое рисование мяча. В активных выбранных кадрах Pong: 700 наблюдений, 389 промежуточных пропаданий в рабочем экране ядра, 0 в опубликованном экране. В Breakout ниже кирпичей: 277 наблюдений, 125 промежуточных пропаданий, 0 в опубликованном экране.
- Отдельно проверены независимые спрайты, замена старого положения без накопления следов, общий набор регистров, точный режим, предел ожидания, очистка, прокрутка, смена режима и два слоя XO-CHIP.
- 31 внешний сценарий Timendus повторно прошёл; конечные экраны совпали с сохранёнными эталонами C-Octo.
- AddressSanitizer/UndefinedBehaviorSanitizer прошли без диагностик; LeakSanitizer отключён из-за ограничения среды.
- Windows x64 EXE собран. Новая оконная версия 2.1 не запускалась на настоящей Windows в этой среде; наблюдаемая плавность на компьютере пользователя требует проверки этой сборки.

Стабилизация остаётся эвристикой для комфортной игры. Она может задержать намеренное удаление объекта до указанного предела и не является универсальным распознавателем игрового кадра любого ROM. Измерения относятся к выбранным кадрам и стандартному seed теста, а не ко всем столкновениям, скоростям и входным событиям.
