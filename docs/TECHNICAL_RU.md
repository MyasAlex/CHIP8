# CHIP-8 Studio 2.1

Переносимое ядро C++20 и приложение Win32 для Windows 10/11 x64. Создано из загруженного проекта `CHIP8-smooth-rendering`, с исправлением ядра, отдельными профилями и новой системой показа кадров.

## Запуск готовой версии

Распакуйте архив и откройте **CHIP8.Emulator.exe**. Программа запускает встроенный Pong на двух игроков. Игры и демонстрация включены в EXE: папка `roms` для запуска не обязательна. Visual Studio, CMake, SDL и отдельные DLL компилятора готовой версии не нужны.

**Pong на двух игроков:** W/S управляют левой ракеткой, стрелки ↑/↓ — правой. В этой игре нет ИИ. Исходный Pong из пользовательского архива сохранён отдельным пунктом меню и имеет собственную логику соперника.

Файлы `.ch8`, `.rom`, `.sc8`, `.xo8` открываются через Ctrl+O, перетаскиванием или аргументом командной строки. `.sc8` выбирает Super-CHIP, `.xo8` и ROM больше 3584 байт — XO-CHIP. Для обычного `.ch8` используется Modern, если ранее не сохранён другой профиль. Автоматической базы определённых по хешу игр нет.

## Управление

| Действие | Клавиша |
|---|---|
| Открыть ROM | Ctrl+O |
| Пауза | P |
| Перезапустить текущий ROM | F1 |
| Сохранить / загрузить состояние | F5 / F8 |
| Снимок PNG | F6 |
| Выполнить кадр / инструкцию | F9 / F10 |
| Полный экран | F11; Esc возвращает окно |
| Отладка | F12 |
| Перемотка назад | Backspace |
| Звук | M |

Стандартные физические клавиши `1234 / QWER / ASDF / ZXCV` соответствуют CHIP-8 `123C / 456D / 789E / A0BF`. Используются сканкоды, поэтому русская раскладка не меняет управление. При потере фокуса клавиши освобождаются, ожидание FX0A переходит к новому нажатию. Автопаузу можно выключить.

XInput: в Pong первый геймпад двигает левую ракетку, второй — правую; D-pad вверх/вниз или левый стик. В остальных ROM: D-pad/стик → клавиши 5/8/7/9; A/B/X/Y/Start → 6/4/0/F/A. Общего редактора назначения клавиш нет.

## Совместимость

| Профиль | Сдвиг | FX55/65 | Логические VF | BNNN | Края спрайта | Ожидание vblank |
|---|---|---|---|---|---|---|
| CHIP-8 (VIP) | VY | I увеличивается | Сброс | V0 | Обрезка | Включено |
| Modern | VX | I сохраняется | Сохраняются | V0 | Перенос | Выключено |
| Super-CHIP Modern | VX | I сохраняется | Сохраняются | VX | Обрезка | Выключено |
| XO-CHIP 1.1 | VY | I увеличивается | Сохраняются | V0 | Перенос | Выключено |

FX0A по умолчанию завершается после отпускания клавиши во всех профилях. Семь особенностей можно менять в меню; изменение перезапускает текущий ROM. Профиль, параметры и скорость сохраняются по отпечатку ROM.

Super-CHIP: разрешения 64×32 и 128×64, спрайты 16×16, прокрутка, большой шрифт, RPL-флаги, 00FD. XO-CHIP: 64 КБ, длинный I с корректными пропусками, два слоя, диапазонные передачи регистров, прокрутка вверх, 128-битный звуковой узор и pitch.

Это интерпретатор инструкций. Исторический Super-CHIP Legacy, CHIP-8X, MegaChip и тактовая эмуляция процессора COSMAC VIP/HP48 не реализованы. Профиль VIP соответствует проверяемым особенностям инструкций, а не всей аппаратуре VIP.

## Экран и время

Таймеры и показ кадров работают с частотой 60 Гц. CPU и таймеры выполняются в порядке временных событий. Длительная остановка хоста не вызывает неограниченного ускоренного воспроизведения: один шаг обработки ограничен 50 мс.

Оконный код читает опубликованный снимок, а не постоянно меняющийся рабочий экран ядра. Изображение масштабируется целым числом, с сохранением пропорций и полями. Каждый кадр полностью заменяется; накопления пикселей и искусственного послесвечения нет.

**Точный экран** показывает состояние на границе кадра. **Стабилизация XOR** отслеживает каждую операцию рисования и удерживает стёртый спрайт до его повторной отрисовки. Мяч, ракетки и другие спрайты обрабатываются независимо; новый спрайт заменяет прежнюю позицию целиком. Если перерисовки нет, удержание истекает через четыре границы кадра, максимум 66,7 мс. Очистка, прокрутка, смена разрешения и восстановление состояния сбрасывают удержание сразу. Это визуальная эвристика: она не меняет RAM, столкновения, инструкции и скорость игры, но может скрыть специально задуманный короткий эффект или немного задержать исчезновение объекта. Для тестов используйте точный экран.

В версии 2.1 исправлено мерцание движущихся объектов в исходном Pong с ботом и Breakout при 700 инструкциях/с. Проверка нормального движения мяча дала 0 пропаданий в 700 выбранных кадрах Pong и 277 кадрах Breakout; состояние ядра в каждом кадре совпало с прогоном без стабилизации. Эти ROM не изменены: проверка байтов совпала с опубликованным набором `kripod/chip8-roms`. Подробнее: [FIX_FLICKER_RU.md](docs/FIX_FLICKER_RU.md).

GDI/DWM не даёт этому проекту гарантии идеального аппаратного VSync. Гладкость конкретной игры зависит также от её ROM, профиля, скорости CPU и системы пользователя.

## Сохранения и звук

`%LOCALAPPDATA%\CHIP8Studio` хранит настройки, состояния, RPL-флаги и PNG. Если Local AppData недоступна, используется `userdata` рядом с EXE. Сохранения содержат версию, отпечаток ROM, контрольную сумму, RAM, регистры, стек, экран, таймеры, RNG, настройки инструкций и аудиоузор. Загрузка сначала проверяет временный объект и затем заменяет ядро целиком. Повреждённый файл и сохранение другого ROM отвергаются. Физические клавиши при восстановлении очищаются; скорость CPU берётся из текущих настроек приложения.

Перемотка хранит до 31 снимка в памяти с шагом около секунды. Она не является записью всех кадров или всех событий ввода.

Звук: waveOut, 48 кГц, четыре буфера по 256 отсчётов. Для CHIP-8 — тон 440 Гц; для XO-CHIP — узор и частота `4000 × 2^((pitch−64)/48)`. Между активными буферами сохраняется фаза. Отсутствие звукового устройства не останавливает CPU.

## Исходники

Основной код находится в трёх файлах: `src/Chip8Core.hpp`, `src/Chip8Core.cpp`, `src/WindowsMain.cpp`. `DemoRom.hpp` содержит массивы встроенных ROM; они генерируются `scripts/generate_demo.py`. Ресурсы, тесты и документация вынесены отдельно.

**Visual Studio:** установите «Разработка классических приложений на C++», откройте `CHIP8.sln`, выберите `Release / x64`, запускаемым проектом назначьте `CHIP8.Emulator`. Используется стандартный набор инструментов установленной Visual Studio. Выход: `bin/x64/Release`. Можно также запустить `build-windows.bat`.

**CMake (Windows или Linux для ядра):**

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release --parallel
ctest --test-dir build -C Release --output-on-failure
```

На Linux собираются ядро и проверки; оконное приложение предназначено для Windows. Python нужен только для внешних ROM-проверок и генератора демонстрации.

В полном архиве находятся `CHIP8.Tests.exe` и `CHIP8.RomRunner.exe`. Офлайн-проверка ROM: `python scripts/verify_roms.py`. Для диагностической проверки окон на Windows: `CHIP8.Emulator.exe --smoke-test smoke`; результат записывается в `smoke/smoke-result.txt`. Этот оконный сценарий в среде подготовки не удалось выполнить.

## Проверено при подготовке

47 групп тестов; 786432 комбинации арифметических операндов с VF; 800 случайных ROM; ASan/UBSan без диагностик (LeakSanitizer отключён из-за ограничений среды); 31 сценарий Timendus с совпадением кадров C-Octo. Windows EXE собран MinGW-w64, проверены тип PE x64, ресурсы и импортируемые DLL. Интерактивное окно, слышимый звук, аппаратный VSync и реальные геймпады на Windows не проверялись. MSVC-проекты предоставлены, но локально собран именно MinGW-вариант.
